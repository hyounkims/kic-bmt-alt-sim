# 대체투자 현금흐름 시뮬레이션 대시보드 — 사용자 가이드

> 이 문서는 실행·데이터 변경·고도화까지 다루는 **개발·운영용 가이드**입니다. 화면 사용법만 필요한 분은 [사용자 매뉴얼](USER_MANUAL.md)을 보십시오.

KIC 대체자산 포트폴리오(12개 펀드, 약정 $3,000mn)의 자금 유·출입(Capital Call / Distribution)과 NAV를
2017년부터 완전 회수 시점까지 시뮬레이션하고, 자산군별 IRR·MoIC 가정 변경에 따른 민감도를 보여주는 대시보드입니다.
모든 계산은 브라우저에서 수행되며 서버나 외부 네트워크를 사용하지 않습니다.

## 2. 화면 사용법

화면은 **2단**입니다. 왼쪽 사이드바에서 조작하고, 오른쪽에서 결과를 봅니다. 민감도 버튼을 누르면 옆의 대표 수치와 차트가 바로 바뀝니다.

| 영역 | 내용 |
|---|---|
| 머리 | 제목, **사용 가이드** 버튼(이 장과 3장 요약을 펼침), **인쇄 / PDF 저장** 버튼 |
| 왼쪽 사이드바 | 보기(범위·기준일), 민감도 조정, 해석 설정. 화면보다 길면 사이드바만 스크롤 |
| 오른쪽 결과 | 대표 수치(기준일 NAV, 예상 최종 Net IRR) → 차트 → 표 탭(시나리오 비교 / 펀드별 성과 / 연도별 현금흐름 / 집행분 상세 / 가정 명세) |

화면 폭이 900px보다 좁으면 사이드바가 결과 위로 쌓입니다.

### 2.1 보기 범위 · 기준일
- **보기 범위**: 대체 포트폴리오 전체 / 자산군(PE·RE·Infra·PD) / 펀드 12개 중 선택합니다.
  - 주소 끝에 붙여 바로 열 수도 있습니다: `#fund:AAA_VII`, `#class:PE`, `#total`
  - 펀드를 고르면 x축이 그 펀드의 약정 연도부터 완전 회수 연도까지로 바뀝니다.
- **기준일**: 운용사 분기 보고에 맞춰 이 날짜 **직전 분기 말**(당일이 분기 말이면 그 분기)까지를 **실현**(채움·실선), 이후를 **추정**(빗금·점선)으로 표시합니다. 입력 아래에 `→ 2026 Q3 말까지 실현`처럼 기준 분기가 나옵니다. 기본값은 2026-09-30(인쇄와 같은 기준일)이며, 날짜를 바꾸면 즉시 다시 계산됩니다.

### 2.2 민감도 조정
- 자산군별로 **IRR**(−6 / −3 / 0 / +3 / +6 %p)과 **MoIC**(−40 / −20 / 0 / +20 / +40 %)를 누르면 즉시 반영됩니다. IRR과 MoIC를 동시에 조정할 수 있습니다.
- 행 왼쪽에 원 가정 → 적용값(예: `18.0% · 2.00x → 15.0% · 2.00x`)이 표시됩니다. PE 행에는 직접투자 XXX의 적용값도 함께 나옵니다.
- **빗금 처리된 버튼**은 조정 후 IRR < 1% 또는 MoIC ≤ 1.0x가 되어 선택할 수 없는 단계입니다(예: RE·PD의 MoIC −40%). 마우스를 올리거나 "비활성 단계"를 펼치면 사유가 보입니다.
- **기본 가정으로 초기화** 버튼으로 모든 조정을 0으로 되돌립니다.

### 2.3 해석 설정 (민감도 패널 하단 "해석 설정")
| 항목 | 선택지 | 설명 |
|---|---|---|
| IRR 조정 해석 | %p 가감(기본) / 상대 변동 | 18% → 15% / 18% → 17.46% |
| MoIC 조정 해석 | 상대 변동(기본) / 절대 가감 | 2.0x → 1.6x / 2.0x → 1.8x |
| NAV 기준 | Gross(기본) / Net | Net은 미실현 이익 × 20%(성과보수)를 차감 |
| XXX 연동 | 체크(기본) / 해제 | PE 조정을 직접투자 XXX에도 적용할지 |

해석을 바꿔 현재 선택한 단계가 하한을 위반하게 되면 해당 단계는 0으로 되돌아가고 알림이 표시됩니다.

### 2.4 대표 수치와 KPI
**기준일 NAV**를 큰 숫자로, 누적 Capital Call·누적 Distribution·DPI·TVPI를 그 옆(좁은 화면에서는 아래)에 **기준 분기 말 시점**으로 표시합니다. 마지막 카드는 **예상 최종 Net IRR**(완전 회수 시점 기준, Net MoIC·회수 완료 분기와 회수일 포함)입니다.
- **기준일 NAV**는 기준 분기 말의 평가가치입니다. 차트 막대와 연도별 표의 **연말 NAV**(각 연도 12월 31일 기준)와 값이 다릅니다.
- 민감도를 조정하면 카드에 "기본 ○○ · 증감"이 함께 표시됩니다.

### 2.5 메인 차트
| 요소 | 의미 |
|---|---|
| 파란 막대 | 연말 NAV. 채움 = 실현(연말이 기준일 이전), 빗금 = 추정 |
| 주황 계단선 | 누적 Capital Call (투자 + 관리보수) |
| 청록 계단선 | 누적 Distribution (회수 총액 − 성과보수) |
| 실선 / 점선 | 기준 분기 말 이전 / 이후 |
| 세로선·배경 빗금 | 기준 분기 말과 그 이후(추정) 구간 |
| 회색 선 | 민감도 조정 시 기본 가정의 누적선 (비교용) |

누적선은 연도 단위가 아니라 **실제 발생일**에 계단이 생깁니다(투자·관리보수 1월 1일, 회수는 MoIC 도달일). 그래서 회수 연도가 같더라도 IRR 변경에 따른 회수 시점 이동을 볼 수 있습니다. 누적 Capital Call은 펀드별 약정액에서 끝나며 포트폴리오 전체 3,000입니다.
연도 위에 마우스를 올리면 그해의 NAV·누적값·당해 흐름(조정 시 기본 가정 값 포함)이 툴팁으로 표시됩니다.

### 2.6 시나리오 비교 탭
기본 / IRR ±3%p / MoIC ±20%를 **전 자산군에 동시 적용**한 결과를 현재 보기 범위 기준으로 비교합니다(종료 연도, 마지막 회수 분기와 회수일, 최종 누적값, 예상 Net IRR·Net MoIC, 기준일 TVPI).
**Δ 마지막 회수(분기 수)·Δ Distribution** 열은 기본 시나리오 대비 차이입니다. 해석 설정이 기본(IRR %p, MoIC 상대)이면 인쇄 요약 표와 같은 수치입니다.
행의 **전 자산군 적용** 버튼을 누르면 해당 시나리오가 민감도 조정에 그대로 반영됩니다.

### 2.7 펀드별 성과 탭
처음에는 전체와 자산군 4개만 보입니다. 행 앞 ▸/▾ 를 눌러 자산군 아래 펀드를 펼치거나, 전체를 접어 전체 행만 볼 수 있습니다(모두 펼치기·모두 접기 버튼 제공).
전체 · 자산군 · 펀드별로 약정, 총 Call, 총 Distribution, 최종 회수 분기(회수일), Gross IRR·MoIC(적용 가정), **예상 Net IRR·Net MoIC**를 보여줍니다.
- LP 순현금흐름: Call(투자 + 관리보수)은 유출, Distribution(회수 − 성과보수)은 유입. Net MoIC = 총 Distribution ÷ 총 Call, Net IRR = NPV가 0이 되는 연 수익률(이분법).
- 현재 보기 범위의 행이 강조되고, 민감도 조정 시 괄호에 기본 가정 값이 나옵니다.
- Distribution 시점은 실제 회수일이므로, 보수가 없는 XXX는 Net IRR이 가정 IRR과 같은 30.00%입니다.
- 기본 가정: 전체 11.46% · 1.55x, AAA VII 12.00% · 1.58x, XXX 30.00% · 2.50x.

### 2.8 연도별 현금흐름 · 집행분 상세 · 가정 명세 탭
탭을 눌러 전환합니다. 긴 표는 탭 영역 안에서 스크롤되고 머리 행이 고정됩니다. 민감도를 바꿔도 보고 있던 탭은 유지됩니다.
- **연도별 현금흐름**: 차트와 같은 값을 표로 봅니다. 구분 열은 실현 / 진행(기준일이 속한 해) / 추정입니다.
- **집행분 상세**: 펀드별 매년 집행분의 IRR·MoIC·t\*(MoIC 도달 기간)·회수 분기(회수일, 예: `2027 Q2 (6/29)`)·회수 총액·성과보수·순회수. 조정 시 괄호 안이 기본 가정 값입니다. 상태 열에는 회수 완료(회수 분기 ≤ 기준 분기) / 보유가 표시됩니다.
- **가정 명세**: 계산에 적용된 원문 가정과 해석 결정을 요약합니다.

## 3. 인쇄 / PDF 저장

화면 오른쪽 위 **인쇄 / PDF 저장** 버튼을 누릅니다. 화면에서 선택한 범위·기준일·조정과 관계없이 **제출용 2페이지**가 고정 조건으로 인쇄됩니다.

| 페이지 | 내용 |
|---|---|
| 1 | 대체 포트폴리오 전체 (2017년 ~ 완전 회수), IRR·MoIC 민감도 소형 차트 2행 × 3열 + 시나리오 요약 표 |
| 2 | PE 포트폴리오 AAA VII (약정 2020년 ~ 완전 회수), 같은 구성 |

고정 조건: 기준일 2026-09-30(2026 Q3 말까지 실현), 전 자산군 동시 적용, IRR %p 가감, MoIC 상대 변동.
차트 격자 위에 열 머리(하향·기본·상향)가 있고, 기본 칸은 굵은 테두리입니다. 6개 차트는 y축이 같아서 y축 숫자는 첫 열에만 표시합니다. 각 차트 캡션과 요약 표에 **기본 대비 차이**(마지막 회수 ±분기, Distribution ±)가 표시되고, 요약 표에는 시나리오별 예상 Net IRR·Net MoIC 열이 있습니다.
각 페이지의 x축은 그 페이지 대상의 5개 시나리오 중 가장 늦은 완전 회수 연도까지입니다.
민감도는 모든 집행분을 조정 가정으로 투자 시점부터 다시 계산한 가상 시나리오이며, 실현/추정은 기준일 기준 표시 구분입니다.

인쇄 창 설정:
| 대상 | 설정 |
|---|---|
| PDF로 저장 | 그대로 저장하면 A4 가로 2페이지 |
| Microsoft Print to PDF · 실제 프린터 | **레이아웃: 가로**, **용지 크기: A4**를 반드시 선택 (기본값 세로면 내용이 90도 돌아간 PDF가 됨) |
| 공통 | 배율 "기본", 배경 그래픽 켜기 권장 |

흑백 인쇄에서도 구분되도록 실현/추정은 채움·빗금과 실선·점선으로, Call/Distribution은 선 굵기로 구분합니다.

## 4. mock 값 변경 방법

현재 입력 데이터는 **파일 한 개**입니다. 화면에서 값을 입력하는 기능은 없으며, 파일을 수정한 뒤 다시 실행·빌드합니다.

### 4.1 파일과 형식: `src/data/portfolio.mock.json`
```json
{
  "funds": [
    { "id": "AAA_VII", "assetClass": "PE", "name": "AAA VII", "type": "fund",
      "commitment": 300, "vintage": 2020, "investPeriod": 4, "gIRR": 0.18, "gMOIC": 2.0 }
  ],
  "fees": { "mgmtInvest": 0.02, "mgmtPost": 0.01, "carry": 0.20 }
}
```
| 필드 | 의미 | 규칙 |
|---|---|---|
| `id` | 펀드 식별자 | 중복 불가, 공백 대신 `_` 권장 (URL `#fund:<id>`에 사용) |
| `assetClass` | 자산군 | `PE` \| `RE` \| `Infra` \| `PD` |
| `name` | 표시 이름 | |
| `type` | 유형 | `fund` \| `direct` (direct는 보수 없음, `investPeriod: 1`) |
| `commitment` | 약정액 ($mn) | 0 초과 |
| `vintage` | 약정 연도 | 정수, 2015 이상 (계산 시작 연도) |
| `investPeriod` | 집행기간(년) | 1 이상 정수 |
| `gIRR` | 연 IRR | 소수 (18% → `0.18`) |
| `gMOIC` | 목표 MoIC | 1.0 초과 |
| `fees.mgmtInvest` / `mgmtPost` | 관리보수율 (집행기간 중 / 이후) | 소수, 약정액 기준. 총 관리보수는 약정 안에서 충당하므로 약정액보다 작아야 함(아니면 `FEE_EXCEEDS` 오류) |
| `fees.carry` | 성과보수율 | 0 이상 1 미만 |

### 4.2 반영 절차
1. `npm run dev` 실행 중이면 파일 저장 즉시 화면에 반영됩니다.
2. 배포·오프라인 파일은 `npm run build` / `npm run build:offline`으로 다시 만듭니다.
3. 형식 오류나 범위 위반이 있으면 계산하지 않고 화면에 **오류 위치와 사유**가 표시됩니다.

### 4.3 값만 바꿀 때와 구성을 바꿀 때
| 변경 | 추가로 필요한 작업 |
|---|---|
| IRR·MoIC·Vintage·집행기간 등 **값만** 변경 (펀드 12개, 약정 합계 3,000 유지) | 없음 |
| **펀드 수나 약정 합계** 변경 | 앱은 시작 시 "펀드 12개·약정 3,000"을 검사해 오류 화면을 띄웁니다. `src/engine/constants.ts`의 `MOCK_FUND_COUNT`, `MOCK_TOTAL_COMMITMENT`를 맞추거나 `src/main.ts`의 `checkMockIntegrity` 호출을 제거 |
| 화면 머리글 문구 | `src/ui/app.ts`의 "12개 펀드 · 약정 $3,000mn" 문구 수정 |
| 인쇄 2페이지 대상 펀드 | `src/ui/print/printView.ts`의 `AAA_VII` 수정 |
| 기준일·계산 시작 연도 | `src/engine/constants.ts`의 `PRINT_AS_OF`(인쇄 기준일), `calcStart`(2015), `displayStart`(2017) |

### 4.4 주의
- 이 파일은 **BMT 제공 원문 데이터**입니다. 제출·발표용 버전에서는 변경하지 않습니다. 실험은 별도 브랜치나 복사본에서 하십시오.
- 값을 바꾸면 원문 대조 테스트(`tests/mock.test.ts`)와 정답 케이스 테스트(`tests/golden.test.ts`)가 실패합니다. Vercel 배포는 `npm test` 통과를 조건으로 하므로 **배포가 중단**됩니다. 로컬 확인(`npm run dev`)과 오프라인 빌드는 테스트 없이도 동작합니다.

## 5. 현재 사용법의 한계

### 5.1 데이터·입력
- 입력은 가정값(약정·Vintage·집행기간·IRR·MoIC·보수율)뿐이며 **실적(실제 현금흐름·NAV)을 받지 않습니다.** 기준일 이전 "실현" 구간도 가정으로 계산한 값입니다.
- 데이터 변경은 파일 수정 + 재빌드로만 가능합니다(화면 업로드·편집 없음).
- 조정 결과를 저장하거나 공유하는 기능이 없습니다(URL로는 보기 범위만 지정). CSV 내보내기가 없습니다.

### 5.2 모델 (원문 가정에 따른 단순화)
- 약정·집행·관리보수는 매년 1월 1일, 집행기간 동안 균등 집행. 관리보수는 약정 안에서 충당: 집행분 = (약정 − 총 관리보수) ÷ 집행기간, 펀드 누적 Call = 약정.
- 집행분은 단일 IRR로 성장하고 **MoIC 달성일에 전액 회수**(원문 가정 4, 부분 회수·재투자·리콜 없음). 회수 금액은 원금 × MoIC, 현금흐름과 Net IRR은 실제 회수일 기준이며, 보고·집계·실현 판정은 그날이 속한 분기 단위입니다.
- 회수일은 연 소수 시각을 그해 일수(365/366)로 환산한 날짜(내림)입니다.
- 민감도로 회수가 늦어지면 관리보수 기간이 늘어 투자금이 줄어듭니다.
- 성과보수는 딜별 (회수액 − 원금) × 20%, 허들·캐치업 없음. 관리보수는 약정액 기준.
- 손실 케이스(MoIC ≤ 1.0x)와 IRR < 1%는 규칙이 없어 선택할 수 없습니다.
- 환율, 세금, 수수료 외 비용, 펀드 레벨 레버리지는 반영하지 않습니다.

### 5.3 민감도
- 조정 단위는 IRR 3%p, MoIC 20%, 최대 ±2단계이며 **자산군 단위**입니다(개별 펀드 단위 조정 없음).
- 민감도는 모든 집행분을 투자 시점부터 다시 계산하는 가상 시나리오입니다. 과거를 실적으로 고정하고 이후만 바꾸는 기능은 없습니다(6장 고도화 참조).

### 5.4 인쇄·배포
- 인쇄물은 고정 조건(기준일 2026-09-30, 전체 + AAA VII)으로만 나옵니다.
- 프린터 드라이버로 인쇄할 때는 레이아웃을 가로로 직접 선택해야 합니다.
- 웹 버전은 Vercel 로그인 또는 Shareable Link가 있어야 접근됩니다.

## 6. 고도화: 실제값(실적)을 적용한 시뮬레이션

목표는 **기준일 이전은 운용사(GP) 보고서의 실적, 이후는 가정·민감도로 시뮬레이션**하는 구조입니다.
엔진은 이미 분기 단위(기준 분기 = 직전 분기 말)로 실현/추정을 나누므로, GP 분기 보고서의 실적을 같은 분기 축에 그대로 얹을 수 있습니다. 기준 분기 말 가치를 계산값 대신 **실제 보고 NAV**로 두고 이후만 시뮬레이션하는 방식으로 확장합니다.

### 6.1 입력 스키마 확장 (예시)
입력의 `portfolio.actuals`는 설계상 예약만 되어 있고 아직 구현되지 않았습니다. 아래는 제안 형식입니다.
```json
{
  "funds": [ ... ],
  "fees": { ... },
  "actuals": {
    "asOf": "2026-09-30",
    "cashflows": [
      { "fundId": "AAA_VII", "date": "2020-03-15", "type": "call", "amount": 70.2 },
      { "fundId": "AAA_VII", "date": "2020-03-15", "type": "fee",  "amount": 1.5 },
      { "fundId": "AAA_VII", "date": "2024-06-30", "type": "dist", "amount": 128.4 }
    ],
    "nav": [
      { "fundId": "AAA_VII", "date": "2026-06-30", "value": 212.5 }
    ]
  }
}
```
- `cashflows`: 분기 보고서의 Capital Call(투자·보수 구분)과 Distribution(순회수). 날짜는 실제 발생일.
- `nav`: 펀드별 최근 보고 NAV와 기준일자(보통 분기 말).

### 6.2 계산 방식
| 구간 | 처리 |
|---|---|
| 기준일 이전 | 이벤트는 `actuals.cashflows`를 그대로 사용. 연말 NAV는 보고 NAV 사용 |
| 기준일 시점 가치 | 최근 보고 NAV를 기준일까지 가정 IRR로 이월 (보고일 = 기준일이면 그대로) |
| 기준일 이후 | 기준일 NAV에서 조정 IRR(r′)로 성장해 **남은 목표 가치**에 도달하면 회수. 관리보수는 기존 일정대로 계속 |
| 약정 미집행분 | 남은 약정액을 집행기간 규칙대로 향후 Call로 생성 |

도입 전에 정해야 할 규칙:
1. **남은 목표 가치의 정의**: 예) 펀드 목표 MoIC × 누적 납입액 − 누적 Distribution. 이미 목표를 넘은 펀드는 기준일 직후 회수로 볼지 여부.
2. **펀드 NAV의 집행분 배분**: 보고 NAV는 펀드 단위이므로 집행분별로 나누는 기준(납입 원가 비율, 빈티지 순서 등).
3. **청산·부분 회수 펀드 처리**: NAV가 0이거나 Distribution이 원가를 넘은 경우.
4. **보고일과 기준일 차이**: NAV 이월에 쓸 수익률(기본 gIRR 등).

### 6.3 반영 위치
| 영역 | 작업 |
|---|---|
| 입력 검증 | 실적 무결성: 펀드 id 존재, 날짜 ≤ 기준일, 금액 ≥ 0, NAV 날짜 유효 |
| 엔진 | 실적이 있는 펀드는 기준 분기 이전을 실적으로 구성하고, 기준 분기 말 보고 NAV에서 출발해 이후를 계산 |
| 화면 | 실현 구간은 실적 값, 추정 구간은 시뮬레이션 |
| 데이터 반입 | 브라우저에서 JSON/CSV 파일을 선택해 읽기(서버 없이, 오프라인 원칙 유지). 분기 보고서 양식 → 입력 형식 변환 템플릿 |
| 테스트 | "기준일 이전 결과 = 실적" 불변 조건, 실적이 없으면 기존 결과와 동일한지 회귀 테스트 |

### 6.4 단계별 진행 (권장)
1. 입력 스키마·검증 규칙 확정과 샘플 실적 파일 작성
2. 엔진: 기준일 이전 실적 + 이후 시뮬레이션, 테스트
3. 화면: 실적 파일 불러오기, 실적/추정 표시
4. 운영: GP 보고서 반입 자동화, AI 에이전트가 시뮬레이션 엔진을 도구로 호출하는 구조와 연계
